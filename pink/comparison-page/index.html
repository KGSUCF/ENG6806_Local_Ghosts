What I learned

Findings

One missing pair of quotes blanked the whole app

gpt-oss wrote var(--bg) where it needed 'var(--bg)'. Browsers refuse to run a script with a syntax error, so every feature failed at once.

The coding model did much better

qwen3-coder worked on the first try, sorted the list and connected every button. After one round of fixes it reached 8 of 10, and its fixes broke nothing new.

Neither local model tested its own work

Both read their code and judged it “fine.” Their summaries claimed undo, share and import worked when they didn’t. gpt-oss’s fix even introduced a new bug in the share text.

A local model will invent data

The prompt gave no dates, but qwen3-coder filled in “last updated” dates from 2023–24 for every restaurant, climbing about a month per row in list order.

How this was done

  • The local models ran in the Ollama desktop app on an AMD Ryzen AI 9 laptop with 96 GB of memory. Both ran entirely on the built-in Radeon graphics.
  • Each local model got one prompt describing the finished Claude app, then one follow-up. gpt-oss was told the browser’s error message; qwen3-coder was told three symptoms in plain words. Both were asked to check for other bugs.
  • The comparison isn’t perfectly even. The Claude version came from several rounds of conversation, and Claude could open the app in a browser and test it between rounds.
  • This page switches off browser pop-ups, so Delete won’t go through in the gpt-oss and qwen3-coder versions here: they ask “Are you sure?” with a pop-up. It worked when tested in a normal browser.
